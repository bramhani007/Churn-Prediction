Instacart Dataset Methodology & Leakage Prevention

Data Leakage Prevention

In grocery retail, predictive churn models must never observe orders placed after the decision point. Our pipeline strictly partitions each customer's order history:

  • Observation Cutoff: Features (recency, interval, reorder ratio, basket size) are computed exclusively on orders $1$ to $N-1$.
  • Evaluation Window: Target churn proxy is determined on order $N$.
  • Temporal Validity: Feature statistics never include subsequent order timestamps, items, or intervals.
Instacart Data Constraints Respected

Unlike standard retail datasets, the Instacart Market Basket dataset has specific limitations:

  • No Ready-Made Churn Label: Instacart only tracks order baskets. We define churn as inactivity $\ge 30$ days (the Instacart order interval ceiling).
  • No Price Data: Instacart does not provide monetary pricing. We strictly avoid fabricating "Average Order Value" or revenues.
  • No Calendar Timestamps: Temporal sequence is governed by order_number and days_since_prior_order.
